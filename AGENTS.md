# Project collaboration preferences

The user wants completed project changes uploaded to GitHub by default.
After implementing and verifying authorized work, commit the relevant changes and
push the current branch to the configured GitHub remote without asking again.
Report the commit and any push failure. Do not force-push, overwrite unrelated
work, or include secrets, local databases, raw facility telemetry, or ignored
dataset caches. Preserve applicable data attribution for published benchmarks.

For requests to brainstorm improvements, propose a focused design before building
new features. The GitHub preference authorizes publishing completed work; it does
not select or approve an unreviewed feature design.

Keep construction and operating costs relatively low. Prefer improvements using
the existing hardware and software. Assess added equipment and recurring costs
before proposing hardware expansion or paid infrastructure.
